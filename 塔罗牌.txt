AI塔罗/MBTI占卜项目需求文档 (PRD) - MVP版一、 项目概况项目名称： （待定，例如：AI灵眸塔罗 / 赛博占星师）产品形态： 微信小程序 / 移动端 H5核心价值： 利用大语言模型（LLM）的文本生成能力，结合塔罗牌阵与用户的MBTI性格特质，提供个性化、有温度、具备一定“神秘感”的占卜解读，满足用户的心理慰藉与娱乐分享需求。二、 目标用户群核心用户： 18-35岁年轻群体，女性偏多。用户特征： 对玄学、星象、塔罗、MBTI感兴趣；面临学业、感情、职场等选择性焦虑；喜欢在社交媒体（朋友圈、小红书）分享心理测试或占卜结果。三、 核心业务流程 (User Flow)进入首页 $\rightarrow$ 选择占卜主题（如：今日运势、感情走向、事业财运）。输入信息 $\rightarrow$ 填写/选择自己的 MBTI 类型（可选填具体问题）。抽牌仪式 $\rightarrow$ 播放洗牌动画，用户手动点击抽取 1~3 张塔罗牌（取决于牌阵）。AI 解析 $\rightarrow$ 前端展示抽到的牌面，后端调用 AI 接口生成专属解读报告。结果展示与分享 $\rightarrow$ 展示精美排版的解析结果，提供“生成分享海报”按钮。四、 功能需求详情1. 首页模块主题选择： 提供3-4个基础占卜方向（单张牌占卜或三张牌占卜）。例如：每日一签、近期桃花运、工作/学业发展、人际关系。个人信息预设： 提供 MBTI 16型人格的选择器，作为后续 AI 生成 Prompt 的关键变量。2. 抽牌交互模块（核心体验）仪式感设计： 需要有洗牌、切牌的UI动效，不能只是简单的按钮点击。这是玄学类应用留住用户的关键。抽牌逻辑： 从标准的 78 张韦特塔罗牌（或仅 22 张大阿尔卡纳牌，降低初期复杂度）中随机抽取，需记录正逆位状态。3. AI 解读生成模块（后端核心）Prompt 组装逻辑： 系统需将用户的输入转化为发送给 LLM 的提示词。公式示例： 你现在是一位资深的塔罗占卜师，面对一位MBTI是 [INFP] 的求问者。TA想问的问题方向是 [感情发展]。TA抽到的牌是：过去-[愚人(逆位)]，现在-[恋人(正位)]，未来-[高塔(正位)]。请结合TA的MBTI性格特质，给出一段带有共情能力、客观且具有指导意义的解读。字数控制在500字左右。加载状态： 由于 AI 生成需要时间（通常 2-5 秒），前端必须有“塔罗师正在冥想感应中...”之类的 Loading 动画进行过渡。4. 结果与分享模块 (裂变核心)结果页展示： 顶部展示抽中的塔罗牌及正逆位，下方呈现 AI 生成的文字解析。海报生成： 提取解读中的“一句话箴言”、用户MBTI、抽到的核心牌面，生成一张高颜值的图片供用户保存发朋友圈。附带小程序码或 H5 链接。五、 商业化变现设计 (建议规划)虽然 MVP 阶段以验证跑通为主，但需要预留商业化接口：免费额度： 每天免费占卜 1 次。广告变现： 观看激励视频广告（如果是小程序）可额外获得 1 次抽牌机会或解锁更深度的解读。付费解锁： 针对特定的复杂牌阵（如：塞尔特十字牌阵），或者生成超过 1500 字的超详细万字报告，采用小额付费（如 9.9 元）。六、 技术架构与开发建议模块技术建议备注前端Uni-app (Vue) 或 原生微信小程序推荐 Uni-app，一套代码可打包小程序和 H5。需重点投入 CSS 动效和 UI 绘制。后端Node.js / Python (FastAPI)需处理并发请求，管理用户的免费/付费额度。AI 接口Kimi (Moonshot), 智谱 GLM, 或 DeepSeek推荐选择国内大模型 API，成本极低，且中文语境下对 MBTI 和塔罗的理解已非常成熟。数据库MySQL + Redis存储用户基础信息、抽牌记录及 AI 缓存（避免重复生成浪费 API 额度）。七、 风险与合规提示平台审核： 微信小程序对“算命、占卜”类目有严格限制。解决方案： 包装成“心理测试”、“性格娱乐”、“星座运势”等合规形式，文案中避免出现“绝对”、“算命”、“改命”等封建迷信词汇，强调“AI心理分析”与“娱乐参考”。这个产品核心拼的不是技术深度，而是 UI交互的“仪式感” 以及 Prompt 调教出来的“情绪共鸣感”。
